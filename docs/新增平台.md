# 新增平台

這份文件說明怎麼把新的斗內平台加進斗內預算管家，以及接下來預計加入的平台。

## 設計原則

- **平台清單只有一份**：`src/lib/platforms.js`。彈出視窗、統計頁、設定頁（連結平台、直播主別名欄）、背景的匯入與自動更新，全部從這裡讀。不要在其他檔案寫死 `'hivebee'`、`'youtube'` 這類清單或 `if` 分支。
- **平台特有的東西留在平台自己的檔案**：頁面解析、翻頁、送出前提醒的位置，放在 `src/content/<平台>.js`（需要的話再加 `src/lib/<平台>.js` 放可測試的純函式）。
- **使用者勾選才連結**：每個平台的網站權限都是選用的（`optional_host_permissions`）。使用者在設定頁「連結平台」勾選並允許後，背景才註冊該平台的 content scripts；沒勾選的網站，擴充功能完全不會讀取。
- **平台和來源分開**：「平台」是錢送去哪裡（直播主在哪收），對應紀錄的 `platform`。「來源」是從哪裡讀到紀錄，例如 Google 付款紀錄讀出來的是 YouTube 和 Twitch 的紀錄。來源放在 `SOURCES`。

## 新增一個平台的步驟

### 1. 在 `src/lib/platforms.js` 登記

在 `PLATFORMS` 加一筆，放在 `manual` 前面：

```js
{
  key: 'ecpay',                 // 紀錄的 platform 值，也是直播主別名的 key；決定後不要改
  label: '綠界',                 // 介面顯示名稱
  color: '--series-5',          // ui/theme.css 的色票 token（--series-1 ～ --series-6，用完再加）
  aliases: true,                // 設定頁直播主表格要不要有這個平台的別名欄
  manual: true,                 // 彈出視窗「手動新增一筆」能不能選
  backfill: ['https://…/紀錄頁'], // 匯入過去紀錄要在背景開的頁面；沒有可讀的紀錄頁就留空陣列
  connect: {
    desc: '讀取……；在……顯示送出前提醒。',  // 設定頁「連結平台」上給使用者看的說明，寫清楚會讀什麼
    origins: ['https://…/*'],    // 要向使用者要的網站權限
    scripts: [
      { id: 'presence', js: ['src/content/presence.js'] },          // 自動更新用：回報使用者正開著這個平台
      { id: 'history', matches: ['https://…/紀錄頁*'], js: ['src/content/common.js', 'src/content/ecpay.js'] },
    ],
  },
},
```

- `scripts` 沒寫 `matches` 時套用全部 `origins`。
- 其他可用欄位：`excludeMatches`、`allFrames`（付款頁在 iframe 裡時）、`world: 'MAIN'`（要讀網頁自己的 JavaScript 變數時）。
- 如果這是「讀紀錄的地方」而不是平台本身（像 Google 付款紀錄），加在 `SOURCES`，並設定 `doneKey`。

### 2. 寫 content script：`src/content/<平台>.js`

用 `common.js` 提供的 `SB` 工具：

```js
(() => {
  const rows = [...document.querySelectorAll('…')].map((tr) => ({
    id: `ecpay:${訂單編號}`,   // 用平台的交易編號去重；前綴是平台 key
    platform: 'ecpay',
    channel: 收款人名稱,         // 拿來對應直播主別名
    amount: SB.parseNumber(金額文字),
    currency: 'TWD',
    time: SB.parseTime(時間文字),
    kind: 'donate',             // 斗內、訂閱、會員……
    counted: 狀態 === '成功',    // 只有付款成功的才計入
  }));
  SB.report(rows);              // 送給背景存起來，並更新角落的本月狀態條
})();
```

- **匯入過去紀錄**：用 `SB.backfill()` 問現在是不是匯入中。是的話自動翻頁，邊讀邊用 `SB.send('backfillProgress', { key, info: { label, count, oldest } })` 回報進度，讀完送 `SB.send('backfillDone', { key })`。`key` 用 `<平台 key>:<分頁名>`，背景收到後會自己關掉分頁。
- **送出前提醒**：在贊助按鈕附近呼叫 `SB.guard(anchor, { platform, channel, amount, currency })`，提醒會出現在 `anchor` 前面。只提醒，不要攔截或改變網站的任何操作。
- 網頁結構會變：選擇器盡量依表頭文字或 `data-*` 屬性，不要依 class 名稱或欄位順序。

### 3. 測試

- 可測試的解析邏輯放在 `src/lib/<平台>.js`，在 `test/<平台>.test.js` 寫單元測試。
- 存一份真實頁面的 HTML 到 `test/fixtures/`。**裡面的直播主名稱、金額、帳號要換成虛構的**，參考現有 fixture。
- `test/e2e.mjs` 可以照 HiveBee 的做法，把網址導向 fixture，跑完整流程。
- `test/platforms.test.js` 會檢查 key 不重複、script id 不重複；新增平台後記得更新裡面列出平台順序的斷言。

### 4. 更新文件

- `manifest.json` 的 `optional_host_permissions` 加上這個平台的網址。
- `CHROMEWEBSTORE.md`：在「網站存取」表格加一列，寫清楚為什麼要讀這個網站；更新商店說明的平台清單。
- `docs/使用教學.md`：如果使用者要做額外設定（例如要先登入、要切到某個分頁），補一段。
- 執行 `npm run docs:shots` 重拍教學截圖。

## 預計加入的平台

以下平台都還沒調查。開始做之前，先用自己的帳號實際付一筆小額，確認下面「待確認」的每一項。

| 平台 | 類型 | 待確認 |
|---|---|---|
| 綠界（ECPay） | 金流，很多實況主用它的贊助頁收款 | 付款人有沒有「我的交易紀錄」頁可以讀；贊助頁上收款人名稱怎麼顯示；交易編號格式 |
| 歐付寶（O'Pay） | 金流，同樣有實況主贊助頁 | 同上 |
| StreamBox | 實況斗內服務 | 有沒有付款人的贊助紀錄頁；需不需要登入 |
| 山羌 | 斗內平台 | 同上 |
| 應援科技 | 斗內平台 | 同上 |

每個平台都要確認：

1. **紀錄從哪裡讀**：平台自己的「交易紀錄」頁、付款完成頁，還是要靠其他來源（例如信用卡、Email 收據）。如果平台沒有給付款人看的紀錄頁，可能只能在付款完成頁當下記一筆，或請使用者手動新增。
2. **網址與網域**：紀錄頁、贊助頁的網址規則，決定 `origins` 和 `matches`。只要求真的需要的網域。
3. **收款人名稱**：紀錄上有沒有直播主名稱，格式為何，拿來對應別名。
4. **去重用的 ID**：有沒有訂單編號；沒有的話用「日期＋金額＋收款人＋當日序號」。
5. **付款狀態**：怎麼分辨成功、失敗、退款。
6. **翻頁方式**：網址分頁、按鈕分頁，還是無限捲動，決定匯入過去紀錄怎麼做。
7. **送出前提醒放哪裡**：贊助金額輸入框和送出按鈕的位置。

調查結果寫回這份文件對應平台的段落，再開始寫程式。
